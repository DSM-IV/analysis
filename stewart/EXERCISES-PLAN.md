# Stewart 9판 연습문제·해설 업데이트 계획

작성일: 2026-09-12. 최신 상태: 사용자 지정 범위 §15.6–15.9, §16.1–16.9, 16장 Review Exercises(사이트 §16.10)의 591문항 작성 및 로컬 통합 완료. 기존 §14.3 시범 8문항을 포함하여 총 599문항. 실제 사이트 배포 전.

아래 초기 단계 계획보다 이번 범위 지정이 우선한다. 완료 내역과 검증 한계는 `EXERCISES-QA.md`에 기록한다.

## 역할 분담 (2026-09-12 착수)

- 총괄: 주 에이전트(Astra). 범위·스키마 조율, 수학 및 사이트 통합 검수, 진행 기록.
- 해설 작성: 별도 Astra 에이전트. 원본 시각 대조, 한영 문제 재서술·힌트·단계별 해설, 검산 기록. 담당 경로: `exercise-content/`, `exercise-checks/`.
- 코드 구현: GPT-5.6 Terra 에이전트. JSON 기반 정적 연습문제 페이지 생성, 한영 패널·수식·토글, 구조 검증. 담당 경로: `build_exercises.py`, `exercises/`.
- 첫 작업 묶음: §14.3 연습문제 9–16번 8개. 이 묶음은 기본 계산형 시범이며 설명·그림·복합 소문항 템플릿 검증은 후속 묶음에서 진행한다.

## 1. 현재 상태와 작업 범위

- 대상 사이트 저장소: `analysis`, 기존 Stewart 페이지: `stewart/`.
- 교재: Stewart, Calculus: Early Transcendentals, 9th edition, 영문판. `SOURCE-MAP.md`에 기록된 로컬 PDF가 존재함을 확인했다.
- 기존 범위: §12.6, §14.1–14.8, §15.1–15.9, §16.1–16.10의 28절. 기존 계획의 완료 기록은 본문 개념과 Example 181개에 관한 것이며, 연습문제 완료를 뜻하지 않는다.
- 이번 작업의 기본 범위: 위 범위의 Exercises와 해설. 16.10 Review는 별도 구분하고, 장별 Review와 Problems Plus도 목록을 만든 뒤 일반 Exercises 다음에 진행한다.
- 교재 전체 업데이트를 원할 경우 나머지 장을 후속 범위에 추가한다. 기존 사이트 범위를 우선하는 것은 착수 순서이며 전체 교재 완료를 의미하지 않는다.
- 이번 지정 범위는 원본 Exercises의 주번호 591개이며 소문항을 함께 포함한다. `exercise-content/manifest.json`이 절별 번호와 총수를 관리한다.

## 2. 문제 목록부터 확정

절별로 문제 번호, 소문항, 인쇄 쪽/PDF 쪽, 공통 지시문, 수식·조건, 그림 필요 여부, 관련 개념, 과제·학습 참고 태그를 기록한다. 공통 지시문을 여러 문항에 적용하는 구간을 특히 확인한다.

`inventory/assignment.txt`는 우선순위 자료로 사용한다. 제출 문항과 참고 문항의 번호가 겹치는 경우 중복 생성하지 않고 두 태그를 함께 붙인다. 101(b) 같은 소문항 지정과 포함 여부 미정 표기도 보존한다.

기존 계획의 제출 문항 제외 방침은 과거 작업 범위로 기록되어 있다. 이번 목록에는 해당 문항도 포함하고, 공개 범위는 명시적으로 관리한다. 번호가 누락된 것을 완료로 처리하지 않는다.

문항 식별자는 판본·종류·절·번호·소문항을 조합한다. 예: `stewart9-exercise-14.3-101-b`. Example, Exercise, Review, Problems Plus는 서로 다른 종류로 저장한다.

## 3. 페이지와 해설 형식

- 기존 개념·예제 페이지에서 해당 절 연습문제 페이지로 연결한다.
- 연습문제는 `stewart/exercises/s14-3.html` 같은 별도 페이지로 구성한다. 기존 언어 선택·수식 표시·풀이 토글을 재사용한다.
- 문제 카드: 출처와 번호 → 문제 요약·수학적 조건 → 관련 개념 링크 → 힌트 → 단계별 해설 → 최종답 → 검산·주의점.
- 한국어 해설을 중심으로 기존 사이트와 일관된 영어 패널을 제공한다. 두 언어의 조건·수식·최종답이 일치해야 한다.
- 풀이에는 방법을 선택한 이유와 적용 조건을 설명한다. 적분 구간, 정의역, 경계·특이점, 방향·법선, 단위 등 문제에 필요한 사항을 생략하지 않는다.
- 문제는 출처 번호와 함께 자체 문장으로 요약하고 해설은 직접 작성한다. 필요한 도형은 자체 제작한다. 원본 PDF는 커밋하지 않는다.
- 목록에는 절·문항 번호·유형·진행 상태를 표시한다. 초기에는 번호 이동과 상태 표시부터 구현하고, 문항이 늘어나면 검색·필터를 추가한다.

## 4. 작업 단위: 문제와 검증된 해설을 함께 완료

각 문항은 `목록 등록 → 원본 대조 → 문제 작성 → 해설 작성 → 수학 검증 → 화면 검증 → 공개 가능` 상태를 거친다. 전체 문제만 먼저 올리고 해설을 나중에 채우는 방식으로 완료율을 높이지 않는다.

1. PDF 페이지를 시각적으로 대조하여 부호·지수·적분 경계·그림 조건을 확정한다. 기존 인벤토리에 기록된 텍스트 추출 오류 때문에 추출 결과만으로 수식을 확정하지 않는다.
2. 문제와 해설을 같은 작업 묶음으로 작성한다. 소문항은 모두 연결하고 공통 조건을 보존한다.
3. 계산형은 재대입·미분·독립 계산 등으로 검산한다. 수치 검산은 보조 수단으로 사용한다.
4. 증명형은 가정과 결론, 정리의 적용 조건, 예외를 검토한다. 그래프형은 자취·절편·경계와 도형을 대조한다.
5. 답지와 불일치하면 독립적인 방법으로 재검산하고 근거를 남긴다. 해결되지 않은 문항은 검토 중으로 유지한다.
6. 링크·언어 패널·토글·모바일 수식 표시까지 통과한 문항만 공개 가능으로 표시한다.

## 5. 실행 순서와 일정 산정

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| A. 목록 확정 | 우선 범위 전체 | 실제 문항·소문항 수, 누락·중복, 그림 필요 목록 확정 |
| B. 시범 제작 | §14.3에서 계산·설명·소문항을 포함한 8–12문항 | 문제·해설·검산·화면을 끝까지 완성하고 실제 소요 시간 기록 |
| C. 1차 업데이트 | §12.6, §14.1–14.6 | 참고 문항 우선, 이후 나머지 일반 연습문제까지 절별 완료 |
| D. 2차 업데이트 | §14.7–14.8, §15.1–15.9 | 최적화·다중적분 문제와 해설, 영역 그림 검증 |
| E. 3차 업데이트 | §16.1–16.9 | 선적분·면적분·적분정리 문제와 해설, 방향 검증 |
| F. 복습·심화 | §16.10 Review, 장별 Review·Problems Plus | 종류별 목록과 해설 완결, 기존 개념에 연결 |
| G. 전권 확장 | 기존 범위 밖의 장 | 전권 요청 시 동일 파이프라인으로 추가 |

일상 작업 묶음은 일반 문항 10–20개 또는 도형·증명이 많은 문항 5–10개로 시작한다. 이는 하루 처리량 약속이 아닌 검토 단위다. 단계 B 이후 난도별 문항 수 × 측정된 작성·검증 시간으로 전체 일정을 산정한다. 오류 수정과 최종 화면 점검 시간을 별도로 반영한다.

## 6. 필요한 산출물과 검증 확장

- `exercise-content/manifest.json` 및 절별 JSON: 문항 식별자, 출처, 종류, 소문항, 상태, 페이지 링크를 관리한다.
- `exercise-checks/`: 문항별 검산 근거와 재현 가능한 계산 스크립트, 불일치 기록을 보관한다.
- `exercises/index.html`, `exercises/s*.html`: 목록과 절별 문제·해설 페이지.
- 기존 `verify_structure.py`는 현재 본문 예제 ID와 페이지 경로를 대상으로 하므로 새 문제 경로·ID·소문항·목록 일치 검사를 추가한다.
- 검증은 누락·중복 번호, 잘못된 링크, 빈 해설·임시 문구, 한영 불일치, HTML·MathJax 오류를 포함한다. 검증 실패 시 실행 결과도 실패로 반환하도록 한다.
- 브라우저에서 긴 수식, 그림 문제, 여러 소문항, 언어 선택, 풀이 펼치기를 데스크톱·모바일 폭으로 확인한다.

## 7. 업데이트 완료 기준

공개 대상 목록의 모든 문항에 문제·필요 소문항·해설·최종답 또는 증명·검증 기록이 있어야 한다. 목록 수와 실제 페이지 수를 대조하고, 미해결 문항을 완료 수에 넣지 않는다. 진행률은 문제 작성 수와 해설 검증 완료 수를 구분해 표시한다.

배포는 검증을 통과한 절 또는 문항 묶음 단위로 준비한다. 첫 계획 이후 사용자의 역할별 모델 분담·진행 요청으로 §14.3 9–16번을 구현했다. 후속 지정 범위 591문항도 로컬 통합했다. §15.6 이전 미작성 절 및 별도의 Chapter 15 Review·Problems Plus는 이번 완료 범위에 포함하지 않는다. 실제 사이트에는 아직 배포하지 않았다.
